# 子进程修改变量，会改变父进程的变量吗？

## 实验条件

参考程序在创建子进程前，把整数变量 `value` 设为 `100`，再通过 `fork()` 创建子进程。每次运行都从这个初始条件开始。

两次运行只改变一个条件：子进程是否把自己的变量改为 `200`。父进程都不修改变量，并且等子进程完成后才输出自己的值。因此，不能把父进程的输出解释为“子进程还没来得及修改”。

这次要核对的是：子进程的修改已经完成后，父进程中的同名变量是否也发生了变化。

## 准备程序

将 [参考源码](fork-private-work.c) 放到 Ubuntu 的实验目录，在该目录的 Bash 终端中编译。需要已有的 GCC，不需要管理员权限。

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror fork-private-work.c -o fork-private-work
```

## 1. 不修改变量，核对共同初值

```bash
./fork-private-work keep
```

观察两行输出：`child` 表示子进程，`parent` 表示父进程。两者的值是否都为 `100`？

参考输出：

```text
child value=100
parent value=100
```

这组结果核对了父子变量的初值相同。仅凭这一组，还不能判断一方修改后是否会影响另一方。

## 2. 只修改子进程的变量，再看父进程

```bash
./fork-private-work change
```

先看子进程是否输出 `200`，确认修改确实发生；再看父进程输出的值，并与第一组对照。

参考输出：

```text
child value=200
parent value=100
```

子进程修改后的值是 `200`，父进程在子进程完成后读到的仍是 `100`。父进程不是观察得太早，而是它自己的变量没有被子进程的修改改变。

## 两组结果说明什么

| 条件 | 子进程输出的值 | 父进程输出的值 |
| --- | ---: | ---: |
| 子进程不修改 | 100 | 100 |
| 只由子进程修改为 200 | 200 | 100 |

`fork()` 后，子进程继承父进程的私有内存内容，因此这个变量的初值相同；父子进程的私有内存随后独立，修改子进程的普通私有变量不会修改父进程的那一份。

由此可以判断：如果要让父进程获得子进程修改后的值，不能只指望父进程重新读取这个同名私有变量，需要通过进程间通信传递数据。

## 程序说明

程序用于对照子进程修改普通私有变量前后，父进程的变量值是否改变。运行格式为 `./fork-private-work MODE`，必须提供一个模式参数。

| 参数 | 作用 |
| --- | --- |
| `keep` | 父子进程都不修改变量。 |
| `change` | 只让子进程把自己的变量从 100 改为 200，父进程不修改。 |
| `--help` | 显示用法，不进行实验。 |

```bash
./fork-private-work --help
```

程序不需要输入数据。正常运行时先输出 `child value=...`，再输出 `parent value=...`，随后自动退出；两次命令是两次独立运行，每次都从初值 `100` 开始。

输出顺序由程序中的等待条件保证，不依赖哪一个进程先获得 CPU。该等待条件用于保证父进程观察发生在子进程完成之后；不会把子进程的变量值复制回父进程。
