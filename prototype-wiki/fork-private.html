fork 创建子进程后的变量变化

参考程序先把变量 value 设为 100，再调用 fork() 创建子进程。原来的进程称为父进程，新创建的进程称为子进程。

这次要弄清楚：子进程把 value 改为 200 后，父进程中的 value 会不会也变成 200？

两次都相同
创建前，value 为 100；父进程不修改变量，并等待子进程完成后才输出自己的值。
两次的区别
第一次，子进程也不修改变量。第二次，子进程把自己的 value 改为 200。
准备程序比较变量值为什么互不影响改变等待时间程序说明

准备程序

下载 参考源码 fork-private-work.c，放到 Ubuntu 的实验目录，在该目录的 Bash 终端中编译。需要已有的 GCC，不需要管理员权限。

gcc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror fork-private-work.c -o fork-private-work

程序输出两行：child 那一行是子进程的变量值，parent 那一行是父进程的变量值。程序保证先输出子进程的值，再输出父进程的值，然后自动退出。

比较父子进程的变量值

第一次运行

1. 父子进程都不修改变量

keep 表示保留原值。先运行这条命令，看看创建子进程后，两者各自读到什么：

./fork-private-work keep

比较 child 和 parent 两行，两个值是否都为 100？

参考输出

child value=100
parent value=100

父进程和子进程都读到 100。因为这次没有修改变量，还不能判断子进程修改后会不会影响父进程。

第二次运行

2. 子进程把 value 改为 200

change 表示让子进程修改变量。重新运行程序，初值仍是 100，父进程仍然不修改：

./fork-private-work change

先看 child 那一行：是不是 200？再看 parent 那一行：它是变成了 200，还是仍为 100？

参考输出

child value=200
parent value=100

child 输出 200，说明子进程确实改了变量；parent 输出 100，说明父进程的变量没有跟着改变。

父进程是不是还没来得及读到新值？

不是。第二次运行时，父进程等到子进程完成后再输出，因此子进程的修改发生在父进程读取之前。为什么修改已经完成，父进程的值却仍是 100？

为什么子进程的修改不影响父进程

fork() 创建的是一个新进程。子进程开始执行时，value 的初值来自创建时的父进程，因此两者最初都为 100。此后，父进程使用自己的 value，子进程使用自己的 value；不是两个进程共同修改一份变量。

操作系统分别保存每个进程的执行状态，并管理它使用的内存。一个进程使用的内存地址及这些地址到物理内存的映射关系，称为它的虚拟地址空间。父子进程各有自己的虚拟地址空间，其中的普通私有变量可以独立修改。

第二次运行中，父子进程的 value 如何变化

父进程

value100

子进程

value200

value 后的数字是变量值，不是变量的内存地址。

初值一样，不代表共用一份变量

创建时继承原值，所以第一次运行输出 100 和 100。子进程后来修改的是自己的变量，所以第二次运行输出 200 和 100。

Linux 怎样在避免立即复制全部内存的同时，保证修改互不影响？

物理内存按页管理，物理页是保存数据的内存单位。刚创建子进程时，父子进程的私有内存可以暂时映射到相同的物理页，避免立即复制所有内容。

这些暂时共享的私有页受到写保护。当一方要写入仍由双方共享的页时，内核为写入方复制这一页，并修改它的映射，再允许写入。另一方仍使用原来的页，内容不变。

这种做法称为写时复制（Copy-on-Write）：需要写入时才复制，而不是创建时就复制全部私有内存。因此，暂时使用同一个物理页，也不代表父子可以直接修改对方的普通私有变量。

变量值的输出没有记录物理页映射。变量也可能被编译器保存在寄存器中，所以不能仅凭 200 和 100 判断这次运行实际复制了哪个物理页。

父进程再等一秒，会读到 200 吗？

假设第二次运行时，父进程在子进程完成后再等一秒。父进程不修改自己的 value，子进程也没有给它传递数据。父进程再次读取自己的 value，会得到多少？为什么？

参考答案

仍是 100。父进程读取的是自己的变量，再等一秒不会把子进程的值传过来。

如果父进程需要取得子进程计算出的 200，就要让子进程把数据传给它，例如通过管道发送，再由父进程读取。管道是进程间传递数据的通道。等待子进程完成，并不等于接收了它的变量值。

程序说明

程序创建一个子进程，分别输出父子进程的变量值。运行格式为 ./fork-private-work MODE，将 MODE 替换为下面的 keep 或 change，不需要其他输入。

keep
父子进程都不修改变量。
change
只让子进程把变量从 100 改为 200，父进程不修改。
--help
显示用法，不进行实验。
./fork-private-work --help

每次运行都从 value 为 100 开始。keep 和 change 是两次独立运行，不是先执行 keep 再修改同一轮程序的值。

正常运行先输出 child value，再输出 parent value，随后自动退出。缺少参数、未知模式或多余参数会显示用法并以失败状态退出。
