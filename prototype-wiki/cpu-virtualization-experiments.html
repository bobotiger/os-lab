CPU 虚拟化实验

先观察 CPU 共享与进程状态，再比较父子进程、程序替换和退出回收，最后追踪系统调用的请求与结果。五项实验都以实际运行记录为依据解释机制。

任务一：CPU 共享任务二：进程状态任务三：fork 与变量任务四：程序替换与进程回收任务五：系统调用与内核控制实验环境需求

任务一 · CPU 共享

一个 CPU，两个计算进程

一个进程单独计算，与两个进程在同一个逻辑 CPU 上计算，完成耗时和计算进度会有什么不同？

观察证据比较最终完成段数、校验值与耗时，再按共同时间排列 A、B 的进度记录，判断两者是否在对方完成前推进了计算。

进入任务一 →
比较条件与机制解释
比较条件
先单独运行 A。第二次重新启动 A，不等它结束就启动 B。每个进程的计算量相同，所有运行都绑定到同一个逻辑 CPU。
机制原因
同一个逻辑 CPU 同时只能执行一个线程。两个单线程进程需要轮流获得 CPU，完成计算的经过时间还包括等待 CPU 的时间。

任务二 · 进程状态

计算、等待与暂停：观察进程状态

等待 CPU、等待管道数据、被信号暂停的进程，状态和 CPU 时间有什么区别？它们分别需要什么条件才能继续执行？

观察证据对照每轮观察的状态记录与 CPU 时间增量，判断哪个进程执行了计算，哪个进程仍在等待或暂停。

进入任务二 →
比较条件与机制解释
比较条件
A 持续计算，B 等待管道中的数据。向 B 发送数据后，再暂停和恢复 A，每次只改变一个条件。
机制原因
等待数据的进程需要数据到达，被信号暂停的进程需要恢复信号。具备运行条件后，进程仍需获得 CPU 才能执行。

任务三 · fork 创建子进程

fork 创建子进程后的变量变化

子进程开始时取得父进程的变量初值。子进程修改变量后，父进程中的同名变量会不会跟着改变？

观察证据比较两次运行中 child 和 parent 输出的变量值，确认子进程已经修改，再判断父进程的值是否改变。

进入任务三 →
比较条件与机制解释
比较条件
两次都从 value 为 100 开始。第一次不修改，第二次只让子进程把自己的 value 改为 200；父进程都等子进程完成后再输出。
机制原因
创建时初值相同，不等于共同修改一份变量。父子进程的普通私有变量可以独立修改；等待子进程完成不会把它的变量值传给父进程。

任务四 · exec 与 waitpid

程序替换与进程回收

装入另一个程序会不会创建新进程？子进程已经退出，父进程还需要等待和回收什么？

观察证据比较替换前后的 PID、程序输出与变量值；再核对 Z 状态、waitpid 返回的 PID 与退出码，以及回收后的记录。

进入任务四 →
比较条件与机制解释
比较条件
第一次使用编译好的目标程序，第二次使用不存在的路径。两次都观察子进程退出后、父进程回收前的状态。
机制原因
exec 替换当前进程的程序，不再次创建进程。退出结束程序执行，waitpid 收集退出状态并回收保留的退出记录。

任务五 · strace 与系统调用

系统调用与内核控制

请求读取 8 字节，为什么只返回 3 字节？读到文件末尾和读取失败怎样区分？程序进入内核处理请求，是否就切换到了另一个进程？

观察证据按文件描述符找到读写对象，比较请求字节数、实际返回值与 EBADF；按 PID 找到创建关系及 execve 的成功、ENOENT 记录。

进入任务五 →
比较条件与机制解释
比较条件
先跟踪 3 字节样本的读取、输出和关闭后的错误，再跟踪任务四程序的创建与替换成功、失败路径。
机制原因
用户程序通过系统调用请求内核服务，内核检查参数并给出结果。进入内核改变执行权限，不等于调度器选择了另一个进程。

实验环境需求

使用 Ubuntu 系统，在 Bash 终端中编译和运行参考程序。原生 Ubuntu 或 WSL 中的 Ubuntu 均可使用。

需要 GCC、Python 3、taskset 和 strace。准备一个可读写的实验目录，用于保存参考源码、编译后的程序和运行记录。
