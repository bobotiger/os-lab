## 页面与模型

- `knowledge-pages.js` 集中维护页面标题、主题、地址和双向关联；只登记已实现的页面。共享知识目录采用“主题 → 知识点”两层结构，主题可折叠，当前知识点有独立高亮；文章的页内导航保持独立。
- `style.css` 是十三页共享的视觉样式。宽度超过 1000px 时显示固定左侧目录；较窄屏幕通过菜单按钮打开模态抽屉，支持关闭按钮、Escape、遮罩点击和选择知识点后关闭，焦点限制在抽屉内。跨过断点时清理模态状态和滚动锁定，不改变演示状态。
- `app.js` 实现进程状态说明。
- `process-api-page.js` 实现父子进程泳道、PID／程序映像／描述符连接、调用片段、输入输出和等待回收观察；`process-api-model.js` 提供独立的成功路径阶段快照，不调用真实系统接口、不操作本机文件、不加载旧引擎。
- `direct-execution-page.js` 实现用户态／内核态执行泳道、播放与回看、CPU 观察、两类保存现场以及受控入口表。`direct-execution-model.js` 提供独立确定性阶段快照，不加载旧引擎，不模拟机器指令，不与调度页共享状态。
- `round-robin.js` 供 FCFS、SJF、SRTF 与轮转页共用，根据页面标识选择引擎策略与知识说明，将确定的调度记录呈现为播放、单步和回看；不保存状态、不联动不同知识页。SJF 有两个、SRTF 有三个固定到达场景，切换时暂停并回到 t=0。
- `mlfq.js` 实现独立的三层就绪队列、时间片与累计配额双计量、分层时间轴、事件说明和进程状态表；提供三个固定行为场景及整体提升开关。`mlfq-model.js` 是仅供此知识页使用的确定性教学模型，生成单位边界快照，不修改旧模拟器的策略合同，也不加载 `simulation-engine.js`。两者使用普通脚本，兼容直接打开本地文件；没有通用负载编辑器或跨页状态。
- `share-page.js` 将彩票与 Stride 放在同一组设置下独立对照，显示票池、pass 决策、目标与实际份额、逐轮分配序列；`share-model.js` 提供确定性教学快照。与 MLFQ 一样使用普通脚本，不加载或修改旧引擎，也不安装新依赖。
- `multiprocessor-page.js` 展示双 CPU 主图、全局或每核队列、迁移、同刻度执行记录和缓存运行关联；`multiprocessor-model.js` 提供独立的两个同速 CPU 教学模型，不修改旧单核引擎。
- `address-space-page.js` 展示双进程虚拟地址布局、私有存储示意、所选地址内容和堆对象／调用帧记录；`address-space-model.js` 提供三种独立、确定性阶段快照，不加载旧引擎。地址空间位于内存主题的分页页之前。
- `paging.js` 实现分页地址拆分、页表映射与物理地址拼接，支持播放、单步、回看与地址输入；与调度页保持状态独立。
- `page-fault.js` 使用现有 `demandPagingScene` 预设生成独立的教学阶段快照，展示缺页和已驻留访问的对照；不是通用虚拟内存模拟器，不修改原始预设。
- `simulation-engine.js` 是生成文件，复用 `src/simulation.ts` 的调度规则与 `src/memory-lab-model.ts` 的地址转换规则，不要手动修改。

修改底层调度或地址转换规则后，在项目根目录重新生成浏览器引擎：

```sh
node scripts/build-wiki-engine.mjs
```

地址空间默认显示 A、B 的示意地址范围 0–15，地址 6 各有值为 10／20 的私有堆对象；读取 A、写入 A 为 99、读取 B 仍为 20、对照结果共五阶段。进程切换与地址选择只改变查看对象，不修改快照；两张图标出同一地址，实线表示当前查看对象，虚线表示另一进程的同址。“程序眼中的内存布局”按代码、静态／全局数据、堆、未使用区域、栈依次介绍，共五阶段；所有区域位置固定，不对应真实平台布局或物理页。

生命周期场景共七阶段：main 活动、调用 work、分配 buffer @ 6、分配 temp @ 7、释放 temp、work 返回、main 释放 buffer。work 返回只撤销该调用帧，不自动释放 main 保留引用的 buffer；释放后地址没有该活对象，不暗示清零或立即归还物理页。A 的生命周期操作不影响 B。物理侧只表示不同位置的私有内容，不标物理地址、不实现转换算法，固定保留存储示意框并标明页状态未展开；代码共享、显式共享内存、物理驻留和真实分配器均未模拟。格子观察不是实际读写，留白或无活对象的位置不返回有效对象内容。

播放、单步、阶段回看、场景切换、区域与地址选择均在页内独立工作。切换场景重新开始；手动观察暂停播放，重置保留场景和速度，后台页面暂停。系统减少动态效果时不执行高亮动画；格子键盘选择保留焦点。窄屏虚拟空间上下排列，物理块和读数仍可完整查看。

多处理器调度页默认“每核队列”开启空闲核取队尾任务。A=8、B=4、C=4、D=2，初始 CPU 0 执行 A、排队 B/C，CPU 1 执行 D。无迁移时 CPU 1 在 t=2 后空闲，全部工作在 t=16 完成；开启时在 t=2 迁移排队 C，t=6 再迁移排队 B，t=10 完成，执行量为 8/10、迁移两次。每核 FCFS，无抢占；只移动未运行的任务，不移动运行者。同一边界先完成两核上一单位工作，再按 CPU 0、CPU 1 顺序派发。总工作量始终为 18，不代表真实调度器知道任务时长或迁移一定更快。

共享队列预设顺序 A/D/B/C，同样在 t=0 派发 A/D；CPU 1 在 t=2 领取 B、t=6 领取 C，t=10 全部完成。取队首必须协调，但不模拟锁竞争耗时；不通过本例证明共享队列优于每核队列。执行记录只画已发生的单位区间，空闲与未演示分别表示；每核队列对照保留同一 16 单位刻度，窄屏局部滚动。迁移开关或场景变化时暂停并回到起点，重置保留设置。

缓存亲和性场景从 A 曾在 CPU 0 执行、重新就绪开始，剩余示意工作为 2，两个核均可用。四阶段展示原关联、重新派发、执行一单位、完成；选择 CPU 1 算一次迁移。累计执行只计算本例这 2 单位，不包含开始前的历史。缓存是运行关联示意，不保证实际数据驻留、不模拟命中率、预热时长或数据复制；隐藏性能时间轴，不能用阶段数比较两条路径性能。页面区分缓存一致性与调度同步、队列组织与选谁的策略；省略 SMT、NUMA、异构 CPU、多线程依赖、I/O 和真实 Linux 调度域。减少动态效果时取消任务高亮动画。

Process API 默认展示 `sort < input.txt > output.txt` 的九个阶段：解析、fork、子进程重定向输入、重定向输出、exec、父进程 waitpid、排序、退出、收集状态。PID 42 的父 Shell 保持终端描述符，PID 43 的子进程先准备连接、再从 shell 映像变为 sort；exec 不改变 PID，成功不返回旧代码。waitpid 的等待、子进程退出后的记录和实际回收分别展示。另有“只有 fork”和“只有 exec”两个四阶段对照：前者停在父子原程序分支，演示结束不表示完成；后者直接替换 PID 42，没有独立父 Shell，外部父进程的回收不在图中。

文件内容固定为 pear／apple／banana，输出预设为排序后的 apple／banana／pear。所有调用预设成功；页面说明 fork／exec 等失败语义，代码是省略检查的调用片段或伪代码，不是完整可编译程序。描述符表独立与底层打开文件引用共享分别解释；0／1／2 没有 close-on-exec 标志，暂存描述符在 dup2 后关闭。fork 返回值保留为教学历史，不意味着 exec 后保留旧程序的局部变量。“可执行”不是 CPU 正在运行；阶段顺序是一种合法教学顺序，不模拟实际调度、并发、信号、真实写时复制或多线程 fork。创建／装载分离提供组合能力，而非唯一设计；posix_spawn 仅解释，不实现。场景变化暂停并回到起点，重置保留场景和速度；窄屏泳道局部滚动，名称保持可见，减少动态效果时取消阶段高亮。

受限直接执行页默认展示计时器中断后切换到 B，也可对照继续 A。单核，A 正在运行、B 已就绪，内核已在启动阶段配置入口和计时器；B 已有合法的用户返回现场及内核上下文。中断入口先保存必要返回状态，OS 再选择是否切换；若切换，A 回到就绪，B 成为运行者，此时 CPU 仍在内核态，随后恢复 B 自己的用户现场。进入内核不等于进程切换，计时器到期也不保证切换；固定选择不是具体调度算法。

系统调用场景包含用户态包装函数、受控入口、内核查询处理、返回 A，不阻塞或切换；其他系统调用可能等待或触发调度。权限场景展示普通指令直接运行及特权操作被拒绝、保护异常接管，停在内核处置入口，不假定异常必然终止或可恢复。阶段不表示真实耗时，演示结束不等于进程完成。入口保存与 OS 上下文切换分别观察；实际寄存器、栈与硬件／软件保存分工依赖体系结构。三类入口表是概念示意，不声称所有体系结构共用一张真实表。场景和中断结果变化时暂停并回到第一阶段，重置保留设置；减少动态效果时不播放阶段高亮动画。

轮转示例采用单核、无 I/O、零切换开销；A、B 同时到达，按顺序入队，CPU 需求分别为 5 和 3。时间片调整范围为 1–5，调整后从头开始。时间轴合并同一进程的连续执行区间，进程间切换计数不包含初次派发，也不包含片满后继续同一进程。

FCFS 使用同一组进程与入队顺序，不设时间片；A 在 [0,5) 执行，B 在 [5,8) 执行，进程间切换一次。CPU 进度表示当前进程已执行的时间，而不是时间片使用量。页面明确说明完成或阻塞会让出 CPU；本例没有 I/O，仅演示完成后的派发。

SJF 复用引擎的非抢占策略，预先确切知道下一段 CPU 时长；只比较已经就绪的任务，时长并列时按就绪入队顺序。本例仍为 A=5、B=3，无 I/O。默认同时在 t=0 到达：B 执行 [0,3)，A 执行 [3,8)，完成后平均等待为 1.5。另一场景 B 在 t=1 到达：此时 A 剩余 4、B 需要 3，但 A 不被抢占；A 执行 [0,5)，B 执行 [5,8)，平均等待为 2。平均等待仅在演示完成后显示；共享控制器按完成时刻减去到达时刻和 CPU 需求计算累计等待，在这两个无 I/O、非抢占场景中等于首次运行时刻减到达时刻。FCFS 平均等待 2.5 的对照仅用于同时到达场景，不泛化为所有场景，也不暗示 SJF 能预知未来到达。页面说明真实系统通常需估计 CPU 段时长，以及持续短任务可能使长任务饥饿；与 SRTF 独立页面互相链接，不提供负载编辑器。

SRTF 是抢占式 SJF，复用现有引擎并沿用 A=5、B=3、无 I/O、零切换开销。默认 B 在 t=1 到达：A 剩余 4，B 需要 3，B 抢占 A；时间轴为 A[0,1)、B[1,4)、A[4,8)，共两次进程间切换。A 恢复时保留已执行的 1 个单位，累计就绪等待为 3，B 等待为 0，平均等待为 1.5；不能把首次响应时间当作累计等待。B 在 t=2 到达的对照中，A、B 均剩余 3，本模型保留运行者 A，时间轴为 A[0,5)、B[5,8)。同时到达时为 B[0,3)、A[3,8)。CPU 空闲时的并列候选按就绪入队顺序选择。页面明确区分抢占、阻塞和时间片轮换；不模拟真实时长预测或切换成本，也不暗示该并列规则是所有系统的唯一实现。

MLFQ 使用单核、零切换开销的明确教学变体：Q0/Q1/Q2 优先级由高到低，片长为 1/2/4，本层累计 CPU 配额为 2/4/8。新进程进入 Q0；选择最高非空队列，同层按队首轮转，不比较预设 CPU 段长度。时间片用完回本层队尾，配额用完降一层并清零两种计数；最低层不再降级，重新轮转。更高层抢占时，原运行者回原层队首并保留两种计数；I/O 阻塞结束本次时间片，但保留层级和累计配额，唤醒后回该层队尾。配额和非最终 CPU 段同时耗尽时先降级再阻塞；最终完成优先于配额耗尽。I/O 使用固定延迟、可并行，无真实设备争用。

MLFQ 默认“降级与高层抢占”：A=14、C=8 在 t=0 到达，B=2 在 t=7 到达；C 此时在 Q1 已用时间片 1/2、配额 1/4，被 B 抢占，t=9 恢复未完成的时间片，总耗时 24。“I/O 不清空累计配额”中，A 连续需要 16，B 有五段各为 1 的 CPU 工作，段间 I/O 等待 2；B 的使用量跨 I/O 累计，仍会降级。“短任务陆续到达”中，A=16，B 至 H 从 t=4 起每隔 2 到达一个、各需 2；开启每 12 单位整体提升时 A 在 t=13 再次获得 CPU，关闭时是 t=18，两者总耗时均为 30。有限到达序列只展示长等待与服务机会，不证明无限饥饿，也不保证提升能让任务更早完成。

整体提升将已到达且未完成的进程恢复到 Q0，清零两种计数；阻塞者仍须等待 I/O，完成者不复活。当前运行者继续，就绪者按原 Q0、Q1、Q2 队列顺序合并。同一边界先处理上一单位的结束，再接收到达和 I/O 完成，随后提升，最后抢占与派发。场景或提升开关变化时暂停并回到 t=0；重置保留设置。窄屏时间轴可横向查看并跟随当前时刻，迁移动画限制在主图内；等待计数只累计就绪等待，不包括 I/O 阻塞。规则、参数和 I/O 简化不代表所有真实系统的 MLFQ 实现。

比例份额页面采用单核、零切换开销、A/B/C 始终就绪的静态竞争集合；每次分配 1 个 CPU 单位。权重预设为 5:3:2（默认）、1:1:1、8:1:1，观察轮数为 12/60（默认）/240，种子为 42（默认）、7、2026、1。权重、轮数或种子变化时暂停并从头开始；重置保留设置。同一权重和种子在不同观察长度下具有相同的彩票前缀，种子不影响 Stride。观察结束不表示三个进程完成；不模拟 I/O、动态加入/退出或运行中调整权重。

彩票调度使用标准 Park-Miller 伪随机递推（乘数 16807，模数 2147483647），种子合法范围为 1 到 2147483646；将状态减一后通过拒绝采样映射到半开票号范围 [0, 总票数)，避免直接取模的不均匀区间映射。它是可复现的教学序列，不是安全随机数或独立随机源的证明。默认票池 A[0,5)、B[5,8)、C[8,10)。票数占比解释为理想均匀抽签的每轮概率，不是有限窗口或等待上界保证；不能从单条序列推断增加观察轮数一定减少偏差。

Stride 使用 stride=120/权重，三个 pass 初值为 0，每轮选择 pass 最小者，并列按 A/B/C 顺序，运行后只给所选者的 pass 加 stride。固定权重均整除 120，因此不引入取整误差。默认权重下第 60 轮分配为 30/18/12，符合 50%/30%/20%；短窗口仍受初始并列顺序影响。pass 是虚拟进度，不是 CPU 剩余时间。页面仅简述加权轮转、WFQ、CFS/EEVDF 的相关思路，不声称这些都等同于本例或已实现。

份额条的实色部分表示实际分配占比，虚线表示权重对应的目标；无样本时实际占比显示为未定义。偏差使用百分点，分配序列只显示已发生的选择；窄屏局部横向滚动并跟随当前轮次。独立模型回归检查：
